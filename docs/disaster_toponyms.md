# 警鐘地名マップ — データパイプラインと設計

日本の警鐘地名（災害地名）を、文字パターンではなく **出典に基づいて** 集約し、
静的な日本地図として公開する仕組みの説明です。

公開先: <https://ut-team-chun.github.io/disaster-toponyms/>

---

## 1. なぜ字面だけでは足りないか

群馬県桐生市の旧小字「梅ヶ久保」は、字面では梅の生えた窪地に見えます。
しかし『桐生市地名考』は次のように記しています。

> 梅は埋の替字で山腹の崩壊で埋まって傾斜地の出来たくぼ。梅ノ木窪とも言う。

災害を示す字は無難な字に置き換えられる（替字・換字）ため、
表記の一致だけを集めても取りこぼし、逆に無関係な地名を拾います。
このプロジェクトは **地誌・地名考・伝承・災害記録という根拠** を構造化して持ちます。

逆の失敗例もあります。広島市安佐南区八木の旧地名として広く報じられた
「八木蛇落地悪谷」は、大蛇退治の伝説が地元の寺に伝わる一方、
広島市郷土資料館は「蛇落地」「悪谷」を記す文献を確認できないとしています。
本データセットはこれを **異説あり** として記録し、反証も出典として並べます。

## 2. 根拠レベル

| レベル | 意味 | 例 |
|---|---|---|
| **0** | 字面のみ。要素辞書に一致するだけの候補 | 全国の「○久保」 |
| **1** | 地名辞典・地誌が地形由来と記載 | 「皿状の浅いくぼのある区域」 |
| **2** | 地方史・地名考・自治体資料が災害由来・替字を明記 | 「間々は崩壊地名。山腹の崩壊で埋まって出来た久保」 |
| **3** | 年号を伴う災害・伝承碑・口承と対応 | 南木曽町の「蛇抜け」×1953年伊勢小屋沢 |

現在のハザードマップとの照合（土砂災害警戒区域・浸水想定区域に入るか）は
**由来とは別の軸** として保持し、UIでも別の見出しで表示します。

## 2.1 地名は点ではなく範囲

地名が指すのは一点ではなく広がりです。ハザードマップとして読むには、
その広がりが警戒区域とどう重なるかが見えなければ意味がありません。

小字の境界は全国では公開されていないため、公開されている最も細かい単位である
**国勢調査の町丁・字等（22 万件）** のポリゴンを使い、各地名が属する区画を描きます。
点はあくまで代表点で、地名が指す場所そのものではないことを UI にも明記しています。
各記録は `location.precision`（小字／大字・町丁目／市区町村）を必ず持ち、
どの解像度で見ているかが分かるようにしています。

ポリゴンは Ramer-Douglas-Peucker で簡略化し、座標を 5 桁に丸めています
（頂点 101 万 → 25 万、約 75% 削減）。

### 守るべき不変条件

このデータセットの価値はレベル分けの厳密さにあります。次を崩す変更を入れないでください。

1. **反証は根拠レベルを上げない。** 出典が由来に疑義を示す場合は
   `Evidence.stance = "disputes"` とし、`disputed` を立てる。
   `evidence_level` は支持する引用からのみ決まる。
2. **レベル2以上には逐語引用が要る。** 引用は `verify_quote` で原資料と
   照合し、一致しないものは破棄する。言い換えや要約を引用にしない。
3. **位置精度を必ず記録する。** 小字は全国のジオコーダに載らないため、
   `Location.precision` に実際の解像度を入れ、UIでも表示する。
4. **レベル0は既定で見せない。** 表記の一致だけを警鐘として提示しない。

## 3. データフロー

```
data/raw/            公開データの取得先（git 管理外・make download-data で再取得）
data/curated/        人手キュレーション（git 管理）
  elements.yaml      地名要素辞典（替字を含む形態素 58 件）
  sources.yaml       出典の書誌情報
  toponyms/*.yaml    全国の代表事例（引用は資料と逐語一致を検証）
      │
      ▼
backend/packages/alg/alg/core/toponyms/
  parsers/     版面（pdftotext -layout）の列構造を復元
  tools/       正規化・要素照合・主張分類・引用検証・ジオコーディング・出力
  pipelines/   取り込み・LLM抽出・候補走査・ハザード照合・出力生成
      │
      ▼
frontend/public/data/    静的ファイル（git 管理・Pages が配信）
  toponyms.geojson       根拠レベル1以上（初回表示）
  candidates/{都道府県}   根拠レベル0の候補
  areas/{都道府県}        地名がカバーする範囲（町丁・字等ポリゴン）
  details/{id}.json      根拠の全文・出典・ハザード照合
      │
      ▼
React Router v7 (SPA) + MapLibre GL JS + 地理院タイル
```

### ステージ

| ステージ | 内容 |
|---|---|
| curated | `data/curated/toponyms/*.yaml` を読み、引用が資料と一字一句一致するか検証 |
| local_history | 『桐生市地名考』の版面を解析し、「崩壊地名」「替字」などの記述から決定的に根拠を付与 |
| prose | 散文資料を LLM で構造化。引用が原文と一致しないものは破棄 |
| geocode | 小字→大字→市区町村の順に位置を解決し、精度を必ず記録 |
| hazard | 各地点でハザードタイルの画素を採取し、区域内かを判定。近隣の伝承碑も紐付け |
| candidates | 全国住所データ 27.7 万行を要素辞書で走査し、根拠レベル0の候補を作成 |
| areas | 国勢調査の町丁・字等ポリゴンを都道府県ごとに取得し、各地名が属する区画を対応づけ |
| outputs | 静的ファイル（地図用・範囲・詳細用・辞典・出典・集計）を書き出し |

## 4. 版面パーサ（`parsers/kiryu_timeikou.py`）

`pdftotext -layout` は印刷時の桁位置を保つため、地名辞典のページは固定列で届きます。

```
蛇           崩                   大蛇が山腹から出てくるとき大きい土砂崩れを起こすとい
                               う伝承から、蛇の字は崩壊を表す。
```

地名は字間を空けて組まれ、語源の解説は詰めて組まれます。この違いを使って
**「3桁以上の空白を含まない行末のブロック」を解説列** と判定します。
村ごとの節は、見出し行 → 現町名の括弧ブロック → 列見出し `字 小字 地名語源` で始まります。

## 5. LLM の役割と制約

散文資料（自治体の防災資料、事典記事）は表形式ではないため、
言語モデルで構造化します。ただし次の制約を機械的に課します。

1. 出力は JSON Schema で固定（`strict: true`）
2. `quote` は資料本文からの逐語引用のみ
3. **引用が原資料に含まれるかを空白無視で機械検証し、一致しないものは破棄**
4. 抽出元を `extracted_by: "llm:<model>"` として記録し、UIに表示
5. 結果は `data/cache/llm/` にキャッシュ。APIキーなしでも再現ビルドできる

モデルには記述の **整理** だけを任せ、内容の創作はさせません。
豊川市資料では 36 件のうち 3 件が引用不一致で破棄されました。

## 6. コマンド

```bash
# 公開データを取得（pdftotext が必要: brew install poppler）
cd backend && make download-data

# データセットをビルドして frontend/public/data に書き出す
cd backend && make build-data

# ネットワークとLLMを使わず、キャッシュのみで再現ビルド
cd backend && make build-data-offline

# 都道府県を絞って試す
cd backend && uv run python packages/alg/scripts/build_toponym_dataset.py --pref 10 --no-candidates

# 品質チェック
cd backend && make fix && make lint && make test

# サイトのローカル確認（GitHub Pages と同じサブパスで配信される）
cd frontend && yarn build:pages && yarn preview:pages
```

`OPENAI_API_KEY` は `.envrc` から読み込みます（`gateways.llm.config.LLMConfig`）。
未設定の場合、LLM 抽出はキャッシュ済みの結果のみを使います。

## 7. 収録を増やすには

1. **自治体の地名考を追加する**（最も効果が大きい）
   郡誌・村誌・小字名索引は自治体ごとに存在します。版面が桐生市と同じ列構造なら
   `LocalHistorySource` を追加するだけで取り込めます。構造が違う場合は
   `PROSE_DOCUMENTS` に加えて LLM 抽出に回します。
2. **要素辞書を育てる**（`data/curated/elements.yaml`）
   `specificity` は「その表記だけで災害履歴を示唆する強さ」です。
   0.55 以上の要素だけが候補走査に使われます。誤検出が増えたら値を下げます。
3. **全国の代表事例を人手で追加する**（`data/curated/toponyms/*.yaml`）
   `verify_against` に `data/raw` 以下の資料ファイルを指定すると、
   引用が逐語一致するかビルド時に検証されます。
4. **国立国会図書館の全文検索を使う**
   次世代デジタルライブラリー（<https://lab.ndl.go.jp/service/tsugidigi/>）で
   著作権保護期間満了の図書 28 万点を全文検索できます。戦前の郡誌や
   地すべり報告に地名由来の記述があります。接続は未実装です。

## 7.1 現在の収録状況

| 区分 | 件数 |
|---|---|
| 出典で裏づけた地名 | 693（レベル3: 10 / レベル2: 211 / レベル1: 472） |
| 字面のみの候補（全47都道府県） | 10,621 |
| 地名がカバーする範囲（ポリゴン） | 4,684 |
| 自然災害伝承碑 | 2,469 |
| 地名要素 | 58 |
| 出典 | 25 |

**根拠付きの地名は群馬県（桐生市）に偏っています。** これは危険が群馬に集中している
という意味ではなく、版面まで解析できた地名考が桐生市のものだけだからです。
候補（レベル0）と伝承碑は全国を覆っているため、地図は全国で使えますが、
根拠レベル2以上の分布は「資料を入れた地域」を表していることに注意してください。
